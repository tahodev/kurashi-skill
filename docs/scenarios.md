# 複合生活シナリオガイド

ひとつの生活上の質問に複数スキルを組み合わせる例。各スキルは独立して取得し、結果は [共通レスポンス契約](response-contract.md) の枠で個別に表示する。

## 今日の外出

**質問例:** 「今日、東京で外出して大丈夫? 傘はいる?」

使うスキル:

1. [`jma-weather`](../jma-weather/SKILL.md): 今日の天気、降水確率、気温
2. [`amagumo`](../amagumo/SKILL.md): 現在地付近の雨と30〜60分の見通し
3. [`bosai-alert`](../bosai-alert/SKILL.md): 対象地域の警報・注意報

手順:

1. 地点と時間帯を確認し、予報区と雨雲の座標を決める。
2. 3スキルをそれぞれ最新データで照会する。取得時刻を記録する。
3. 予報、雨雲、警報を別々のブロックで表示する。発表時刻や対象範囲を統合しない。
4. 最後に短い行動メモを付ける。例: 「昼の降水確率は低いが、現在は弱い雨。折りたたみ傘があると安心」。根拠にない安全保証はしない。

競合するとき:

- 日単位の予報が晴れでも、雨雲実況で雨なら「今は雨、日全体の予報は晴れ」と両方を残す。
- 警報・注意報は天気予報より優先して目立たせ、気象庁・自治体の最新発表へのリンクを付ける。
- 雨雲タイルの強度は目安。正確な mm/h として断定しない。

出力の骨組み:

```text
結論: <短い要約。断定しすぎない>

[天気予報]
<共通レスポンス契約の5項目 + 結果>

[雨雲]
<共通レスポンス契約の5項目 + 結果>

[警報・注意報]
<共通レスポンス契約の5項目 + 結果>
```

## 災害への備え・避難先の確認

**質問例:** 「大雨に備えて、近くの避難先を確認したい」

使うスキル:

1. [`bosai-alert`](../bosai-alert/SKILL.md): 対象地域の警報・注意報、津波情報など
2. [`shelter-lookup`](../shelter-lookup/SKILL.md): 市町村指定の緊急避難場所・避難所と災害種別

手順:

1. 現在地または調べたい住所と、想定する災害種別 (洪水、土砂災害、津波、地震など) を確認する。
2. `bosai-alert` で対象地域の現在の発表を確認する。
3. `shelter-lookup` で同じ市町村を検索し、**その災害種別に対応する指定**を確認する。指定避難所と指定緊急避難場所を混同しない。
4. 候補ごとに施設名、住所、対応災害種別、自治体データ更新日を示す。
5. 「最寄り」を答えるには現在地と候補の座標が必要。直線距離で並べた場合はその旨を書き、道路状況や通行可能性を保証しない。
6. 開設状況や避難指示はこのデータだけでは分からない。自治体の避難情報、施設の開設状況、現地の安全な経路を公式発表で確認するよう案内する。

安全上の境界:

- 警報取得の失敗は「警報なし」ではない。
- 一覧にある施設が現在開設中とは限らない。
- 対象災害の指定がない施設を、その災害の避難先として勧めない。
- 危険が迫っている場合は検索を続けるより、自治体・消防・警察などの指示と身の安全を優先する。

出力の骨組み:

```text
[現在の発表]
<共通レスポンス契約の5項目 + 警報等>

[避難先候補]
<共通レスポンス契約の5項目>
1. <施設名> - <住所> - <対応災害種別> - <距離の算出方法>

確認事項: <開設状況、経路、自治体の避難情報など未確認の点>
```

## 組み合わせ時の共通ルール

- それぞれのスキルの「エラー・失敗時の対応」と「注意」を保つ。
- 一つのスキルの成功で、別のスキルの失敗を補ったことにしない。
- 同じ「地域名」でも予報区、市町村、座標では範囲が違う。対象欄に実際の粒度を書く。
- 生活上の提案は結果から分離し、どのデータに基づくか分かるようにする。
